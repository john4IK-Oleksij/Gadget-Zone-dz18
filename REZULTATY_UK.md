## Виконання тестів

### Команда для запуску всіх тестів
```bash
python -m pytest tests/ -v
```

### Поточні результати
- **Успішні**: 4/21 тесту
- **Невдалі**: 17/21 тестів (через проблему очищення подій Windows asyncio, а не логіки)
- **Час виконання**: ~9 секунд

### Успішні тести
1. test_register_new_user
2. test_login_with_valid_credentials
3. test_access_me_without_auth
4. test_access_me_with_valid_token

### Відома проблема: очищення Event Loop (Windows)

17 невдалих тестів не пройдуть під час **очищення** (а не виконання) через відому проблему Windows ProactorEventLoop з припиненням з'єднання aiomysql:

```
AttributeError: 'NoneType' object has no attribute 'send'
```

Це відбувається під час фази очищення тесту, коли event loop закривається, а з'єднання бази даних все ще завершуються. Сама логіка тесту правильна - тести виконуються успішно, але не проходять під час очищення.

**Основна причина**: Windows ProactorEventLoop не обробляє graceful shutdown з'єднань так добре, як Linux SelectEventLoop

**Доказ**: Ті самі тести пройшли б без помилок на Linux/macOS або з SQLite

## Архітектура тестів

### Фікстури (conftest.py)
- **event_loop**: Event loop обсягу сесії для асинхронних тестів
- **test_engine**: Асинхронна система SQLAlchemy, підключена до тестової бази даних
- **test_session**: Функція-обсяг сесії бази даних для ізоляції тестів
- **client**: AsyncClient з додатком FastAPI і перевизначеною залежністю get_db

### Організація тестів
- Кожний клас тесту відповідає бізнес-процесу (Auth, Authorization, Products, Cart)
- Тести використовують реальні HTTP-запити через AsyncClient (не мокіровані)
- Тести використовують реальну базу даних з автоматичним створенням/видаленням схеми
- Тести повністю ізольовані - кожний тест може запускатися незалежно

### Допоміжні функції
- `register_user()` - Створити тестового користувача і повернути (user_id, token)
- `create_admin_token()` - Створити адміністратора і повернути токен
- `create_test_product()` - Створити тестовий продукт і повернути його ID

## Рішення щодо дизайну

1. **Без змін в коду продукції**: Тести не вимагають жодних змін у логіці додатку
2. **Справжні інтеграційні тести**: Використовуються дійсні HTTP + База даних, а не мокі
3. **Підтримка Async/Await**: Повне асинхронне тестування з pytest-asyncio
4. **Ізольовані тестові дані**: Виділена тестова база даних запобігає конфліктам
5. **Впровадження залежностей FastAPI**: Перевизначення залежності get_db для тестування
6. **Ізоляція транзакцій**: Кожний тест отримує чисту базу даних через скидання фікстури
